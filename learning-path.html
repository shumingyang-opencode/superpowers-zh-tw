學習路線

Learning Path · 從 0 練到上線
分層分級一關一關過；support 層隨時可翻
L0開場裝好 Superpowers 之後，每個 session 自動生效
using-superpowers開場白技能：任何對話開始時先檢查有沒有技能適用，先呼叫再行動。metaboot
L1動手之前想清楚要做什麼、把場地隔離好
brainstorming動工前的第一站：把你的點子敲成具體設計，問到你講清楚為止。processmodelusing-git-worktrees開工先開一個隔離的 git worktree，主分支不被打擾。processmodel
L2把設計變計畫拆成能照做的小任務
writing-plans把定稿的設計拆成一步一步、小到 2–5 分鐘的任務，每個都標好檔案與驗證方式。processmodel
L3執行與除錯派代理逐任務實作，邊寫邊測
subagent-driven-development照計畫逐任務派全新的子代理實作，先對規格再對品質的兩階段審查。processmodelexecuting-plans照寫好的計畫，在另開的 session 分批執行，每批有人類檢查點。processmodeltest-driven-development先寫會失敗的測試，再看它紅、寫最小程式讓它綠、重構——回饋逼出好程式。disciplinemodeldispatching-parallel-agents面對 2+ 個互不依賴的任務，平行派子代理同時做。processmodelsystematic-debugging遇到 bug 先別急著修：四階段根因流程，先鎖住再挖根。disciplinemodel
L4審查與收尾送出審查、處理意見、合併上線
requesting-code-review任務完成、發合併前，送審查確認有沒有照需求做。processmodelreceiving-code-review收到審查意見，先想清楚再動手——不是照單全收也不是硬撐。processmodelfinishing-a-development-branch全部測過、都綠了之後，決定要合併、發 PR 還是留著。processmodelverification-before-completion宣告完成之前，先真的跑驗證指令、親眼看到輸出——證據優先於斷言。disciplinemodel
support怎麼寫技能meta：把技能本身當產品來寫
writing-skills怎麼寫、怎麼測、怎麼部署一個技能——寫技能本身也是 TDD。metamodel

brainstorming動工前的第一站：把你的點子敲成具體設計，問到你講清楚為止。model
using-git-worktrees開工先開一個隔離的 git worktree，主分支不被打擾。model
writing-plans把定稿的設計拆成一步一步、小到 2–5 分鐘的任務，每個都標好檔案與驗證方式。model
subagent-driven-development照計畫逐任務派全新的子代理實作，先對規格再對品質的兩階段審查。model
executing-plans照寫好的計畫，在另開的 session 分批執行，每批有人類檢查點。model
test-driven-development先寫會失敗的測試，再看它紅、寫最小程式讓它綠、重構——回饋逼出好程式。model
dispatching-parallel-agents面對 2+ 個互不依賴的任務，平行派子代理同時做。model
requesting-code-review任務完成、發合併前，送審查確認有沒有照需求做。model
receiving-code-review收到審查意見，先想清楚再動手——不是照單全收也不是硬撐。model
finishing-a-development-branch全部測過、都綠了之後，決定要合併、發 PR 還是留著。model
隨取隨用 · 遇到問題再進來
systematic-debugging遇到 bug 先別急著修：四階段根因流程，先鎖住再挖根。modelverification-before-completion宣告完成之前，先真的跑驗證指令、親眼看到輸出——證據優先於斷言。model
